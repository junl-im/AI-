# 0.11.71 · 기본 성우 소리 직접 저장 진단

2026-10-23 KST. 브라우저 `SpeechSynthesisUtterance`는 선택한 성우로 재생하지만 생성 PCM/WAV 바이트를 페이지에 돌려주지 않습니다. 화면 공유·입력 장치 캡처가 무음인 PC에서 무음 WebM을 WAV/MP3로 바꾸는 것으로는 해결할 수 없습니다.

이번 버전은 Windows에서 실제 출력되는 음성을 [NAudio의 WASAPI 시스템 루프백](https://github.com/naudio/NAudio/blob/main/Docs/WasapiLoopbackCapture.md)으로 잡는 보조 앱을 추가했습니다. 웹은 대사마다 원래 브라우저 성우를 다시 재생하면서 보조 앱의 캡처를 시작·중지하고, 받은 WAV를 타임라인 쉼 구간과 합쳐 MP3로 변환·다운로드합니다. Windows 보조 앱 ZIP은 사이트 저장 화면에서 직접 받을 수 있습니다. 앱은 `127.0.0.1:18717`에만 수신하고 일회 실행 토큰과 허용 출처를 검사합니다. 다른 앱의 출력 소리도 파일에 들어갈 수 있습니다.

실제 검증: 자체 포함 Windows x64 **폴더형** 배포판이 이 PC에서 실행됐고, 허용 출처 CORS 사전 요청 204, 토큰 있는 상태 200, 토큰 누락 401, 다른 출처 403을 확인했습니다. Microsoft Heami가 소리 내어 읽은 문장을 WAV 1,953,338바이트(RIFF)로 캡처했으며 피크 0.5946, RMS 0.08175로 무음이 아닙니다. Chrome의 로컬 네트워크 권한을 부여한 시험 프로필에서 GitHub Pages 출처→보조 앱 `/status` 200도 확인했습니다. 별도의 Chrome 로컬 개발 페이지에서 소리온 프리셋 `sori-warm`이 Heami를 선택한 뒤 **실제 브라우저 음성 재생→보조 앱 캡처→웹 WAV 결합→MP3 변환→파일 다운로드**를 통과했습니다. 내려받은 `sorion-browser-original.mp3`는 113,684바이트, MPEG 헤더 `FF FB 90 C4`이며 Chrome 재디코딩 피크 0.551로 무음이 아닙니다. 저장 UI의 보조 앱 연결·다운로드 회귀 테스트와 전체 웹 테스트도 통과했습니다.

검증의 경계: 실제 MP3 시험은 이 PC의 **Chrome 로컬 개발 페이지에서 앱의 저장 함수를 호출**한 결과이며 배포된 Pages의 저장 버튼을 직접 클릭한 시험은 아닙니다. GitHub Pages 출처의 로컬 연결만 별도로 확인했습니다. 설치된 한국어 Windows 음성은 Microsoft Heami 여성 한 종류여서 다섯 기본 성우의 원본 자산·음색 일치를 주장할 수 없습니다. 다른 PC·Edge에서의 실행과 재생도 아직 확인하지 못했습니다. 기본 성우가 실제 출력되지 않거나 다른 출력 장치를 쓰면 보조 앱도 무음이 됩니다. Chrome/Edge는 공개 페이지의 로컬 앱 연결 시 ‘이 기기의 앱 접근’ 권한을 요구하며, 거부하면 연결되지 않습니다.

단일 파일 EXE는 이 테스트 샌드박스의 임시 추출 디렉터리에 쓰지 못해 실행에 실패했습니다. 최종 배포는 임시 추출을 쓰지 않는 폴더형 자체 포함 ZIP으로 만들었고 실행·녹음을 검증했습니다. NAudio.Wasapi 3.3.0은 [MIT 라이선스](https://github.com/naudio/NAudio/blob/main/LICENSE)이며 ZIP에 라이선스 사본이 들어 있습니다. 사용 중인 `WasapiLoopbackCapture`는 NAudio 3에서 레거시로 표시되므로 후속 버전에서 최신 `WasapiRecorder` 이전을 검토합니다.
