# LINKED PLAYER DOCK

## 0.10.3 PC compact Dock

- PC 일반 Dock은 플레이어와 주요 메뉴를 같은 얕은 행에 배치합니다.
- 만들기 전용 Dock은 진행바 1줄과 정보·조작 1줄로 줄이고 큰 원형 모바일 버튼은 PC에서 사용하지 않습니다.
- 모바일은 기존 터치 크기와 safe area를 유지합니다.
- 종료된 트랙의 재생 버튼을 다시 누르면 0초부터 재생합니다.
- 타임라인 seek 요청은 같은 단일 플레이어의 현재 위치와 resume 위치를 함께 갱신합니다.

## 목적

SoriON의 모든 음원은 화면마다 별도 플레이어를 만들지 않고 하단 Dock의 단일 `audio` 요소에 연결한다. TTS 생성 결과와 복제 원본 샘플이 같은 재생 규칙을 사용한다.

## 0.6.4 적응형 표시 규칙

- 음원이 없을 때는 하단 주요 메뉴만 표시한다.
- 생성 또는 복제 음원이 준비되면 연계형 플레이어를 표시한다.
- 플레이어는 모바일과 PC 모두 주요 메뉴보다 위에 배치한다.
- 플레이어가 사라지면 본문 하단 안전 여백도 메뉴 높이에 맞게 줄인다.
- Dock은 앱 배경과 연결되는 기존 어두운 반투명 톤을 유지한다.
- 대기열을 모두 비우면 플레이어와 대기열 패널을 함께 닫는다.

## 플레이어 기능

- 최대 20개의 재생 대기열
- 현재 음성 자동 선택
- 이전·다음 음성
- 파형 영역 클릭 탐색
- 현재 시간과 전체 시간
- 반복 끔, 전체 반복, 한 곡 반복
- 0.75배부터 2배까지 재생 속도
- 현재 음원 다운로드
- 대기열 개별 삭제와 전체 비우기
- 새 TTS 결과와 복제 샘플 자동 연결

## 소유권과 메모리

브라우저에서 생성한 Object URL은 `revokeOnRemove`가 설정된 트랙만 Dock store가 관리한다. 트랙 삭제, 대기열 비우기, 20개 초과 제거 시 `URL.revokeObjectURL`을 호출한다. API의 일반 HTTP URL은 해제하지 않는다.

## 재생 대기열 규칙

- 새 음원은 대기열 마지막에 추가하고 현재 음원으로 선택한다.
- 반복 끔 상태에서 마지막 음원이 끝나면 정지한다.
- 전체 반복은 마지막에서 첫 음원으로 이동한다.
- 한 곡 반복은 같은 음원을 처음부터 다시 재생한다.
- 재생 중 이전·다음 이동 시 새 음원이 준비되면 재생을 이어간다.

## 반응형

모바일과 PC 모두 플레이어와 메뉴를 세로로 쌓는다. 플레이어가 존재할 때 순서는 항상 `플레이어 → 메뉴`다. PC에서는 두 프레임 전체 폭에 맞춘 Dock을 사용하고, 재생 대기열은 Dock 위에 독립 패널로 열린다.

## 0.6.4 메뉴 이동 규칙

- Dock 메뉴의 전체 버튼 영역을 터치 대상으로 사용한다.
- 메뉴 클릭 시 페이지 상태를 바꾸고 화면 상단으로 부드럽게 이동한다.
- 음성이 준비된 경우에도 플레이어가 메뉴 위에 유지된다.
- active 메뉴는 pill 배경과 inner shadow로 눌린 상태를 표현한다.

## Engine Heartbeat 6 부분 트랙과 지연 지표

- 장문 첫 구간은 `partial` 메타데이터를 가진 임시 트랙으로 연결하고 `N개 중 1번째 구간`을 표시합니다.
- 최종 WAV가 준비되면 임시 트랙을 새 항목으로 추가하지 않고 같은 ID에서 교체합니다.
- 부분 object URL은 최종 교체·삭제·대기열 비우기 때 해제합니다.
- 서버 첫 구간, 첫 바이트, 실제 `playing`, Browser Speech `onstart`를 서로 다른 telemetry 값으로 유지합니다.
- 존재하지 않는 지표는 0ms로 표시하지 않습니다.


## Engine Heartbeat 6.1 최종 음원 handoff

- 같은 트랙 ID의 `partial` URL이 최종 WAV URL로 바뀌면 현재 재생 시간과 재생 중 여부를 캡처합니다.
- 새 파일의 metadata가 준비된 뒤 가능한 범위로 시간을 제한해 복원하고, 교체 전 재생 중이었다면 재생을 이어갑니다.
- 일시정지 상태의 위치도 보존하되 사용자가 누르지 않은 자동 재생은 새로 시작하지 않습니다.
- URL 만료로 새 서명을 받지 못한 부분 파일은 대기열에 등록하지 않고 최종 결과를 기다립니다.


## Engine Heartbeat 6.2 ordered segment queue

- 부분 트랙은 `progressive.segments`에 준비된 WAV를 번호순으로 보관합니다.
- 현재 구간이 끝나면 다음 번호를 재생하고, 아직 없으면 `다음 구간 대기` 상태로 멈춥니다.
- 대기 중 새 구간 또는 최종 WAV가 도착하면 같은 트랙 선택을 유지하며 자동으로 재생합니다.
- 최종 WAV handoff 위치는 완료한 구간의 누적 시간과 현재 구간의 native currentTime을 합산합니다.
- 부분 재생 중에는 전체 길이 기준 seek와 다운로드를 비활성화합니다.
- 구간 Blob URL은 교체·삭제·중복 제거 시 모두 revoke합니다.


## Engine Heartbeat 6.3 seam·새로고침 복원

- 부분 구간은 이전 `ended`부터 다음 `playing`까지 전환 시간을 기록하고 대기 포함 여부를 표시합니다.
- 최종 원격 음원은 timeupdate 기준 마지막 위치를 저장하고 25분 이내 새로고침에서 복원합니다.
- 복원 직후 자동 재생은 하지 않으며 사용자가 재생 버튼을 눌러야 합니다.
- 부분 음원·Blob URL·만료 서명 URL은 복원하지 않습니다.


## Engine Heartbeat 6.4 signed final audio recovery

최종 API 트랙은 작업 ID를 보존하고 새로고침 또는 media error에서 완료 결과를 다시 조회해 새 HMAC URL을 받습니다. 재발급 성공 시 트랙 ID, 제목, 저장 위치와 재생 의도를 유지합니다. 서버 파일 TTL이 끝난 경우에는 반복 요청하지 않고 다시 생성을 안내합니다.

## 0.9.7 자연스러운 재생 버튼 순서

- 사용자가 `재생`을 누르면 실제 media `play` 이벤트를 기다리지 않고 즉시 `일시정지`로 전환합니다.
- 준비 중 또는 재생 중 `일시정지`를 누르면 pending 재생까지 멈추고 버튼을 `재생`으로 복원합니다.
- 파일 음원과 Browser Speech가 같은 상태 계약을 사용합니다.
- Browser Speech는 실행별 run ID를 사용해 취소된 utterance의 늦은 callback을 무시합니다.
- 버튼은 동적 접근성 이름과 `aria-pressed`로 현재 상태를 전달합니다.
