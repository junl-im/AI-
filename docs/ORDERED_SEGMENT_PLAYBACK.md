# Ordered Segment Playback

현재 기준: `0.9.3-beta.3 · Engine Heartbeat 6.4`

## 목적

장문 생성 중 첫 번째 WAV만 재생하고 멈추던 경로를 확장해, 두 번째 이후 준비 구간도 **작업의 구간 번호 순서**로 하나의 Player Queue 트랙에서 이어 재생합니다. 이 기능은 여러 완성 WAV 파일을 순차 교체하는 방식이며 PCM/WebSocket 스트리밍이 아닙니다.

## 순서 보장

- SSE와 polling에서 구간이 뒤섞여 도착해도 coordinator는 `nextSegmentIndex`부터 처리합니다.
- 아직 앞 번호가 준비되지 않은 후속 구간은 메모리 대기열에 보관합니다.
- 같은 구간 번호를 중복 수신하면 한 번만 등록합니다.
- 서명 URL은 모든 구간에서 403·410 시 작업 상태를 다시 조회해 한 번 재발급합니다.
- 앞 구간을 받을 수 없으면 뒤 구간을 건너뛰어 재생하지 않고 최종 WAV를 기다립니다.

## 플레이어 상태 전이

1. 1번 구간이 준비되면 기존 대기열에 부분 트랙을 만듭니다.
2. 2번 이후 구간은 같은 트랙의 `progressive.segments`에 번호순으로 누적합니다.
3. 현재 구간이 끝났는데 다음 구간이 아직 없으면 **다음 구간 대기** 상태로 정지합니다.
4. 다음 구간이 도착하면 사용자 선택과 트랙 ID를 유지한 채 자동으로 재생합니다.
5. 최종 WAV가 준비되면 누적 완료 구간 시간과 현재 구간 위치를 합산해 최종 파일의 재생 위치로 승계합니다.
6. 부분 재생 중에는 전체 파일 기준 seek와 다운로드를 제공하지 않습니다.

## 메모리와 URL 수명

- 브라우저가 내려받은 구간 Blob URL은 트랙 교체·삭제·대기열 비우기 때 모두 해제합니다.
- 중복 구간에서 새로 만들어진 Blob URL도 즉시 해제합니다.
- 서버 단기 URL은 영구 저장하지 않으며 페이지 복원 시 작업 ID로 새 URL을 조회합니다.

## 현재 제한

- WAV 파일별 `audio` source 교체이므로 decode 경계에 짧은 틈이 생길 수 있습니다.
- 실기기에서 구간 사이 무음 시간을 측정하기 전에는 **gapless** 재생으로 표현하지 않습니다.
- 다음 구간을 미리 내려받아 Blob으로 보관하지만 브라우저별 decode·autoplay 정책은 다를 수 있습니다.
- 최종 WAV가 오기 전에는 전체 길이가 확정되지 않아 부분 재생 seek를 차단합니다.


## Engine Heartbeat 6.3 seam 측정

- 현재 구간의 `ended` 이벤트 시각을 저장하고 다음 구간의 실제 `playing` 이벤트에서 차이를 계산합니다.
- 다음 구간이 늦게 도착한 전환은 생성 대기 포함으로 구분합니다.
- 트랙별 최근 20개 측정만 보존하며 Quality Lab에서 평균·최대·최근 전환을 확인합니다.
- 이 값은 생성 대기·fetch·decode가 함께 포함될 수 있어 단독으로 gapless를 증명하지 않습니다.
