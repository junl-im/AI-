# Partial Audio Delivery

현재 기준: `0.9.3-beta.3 · Engine Heartbeat 6.4`

## 목적

장문 음성 생성이 끝날 때까지 기다리지 않고 준비된 WAV 구간을 번호순으로 Web 플레이어에 연결합니다. 이 경로는 진짜 스트리밍 코덱이 아니라 **파일 단위 부분 전달**입니다. 최종 WAV가 완성되면 같은 대기열 트랙의 음원을 교체하므로 대기열 순서와 선택 상태가 유지됩니다.

## 서버 흐름

1. TTS Pipeline이 장문을 구간으로 나눕니다.
2. 각 구간 WAV가 완성되면 작업 스냅샷의 `ready_segments`에 메타데이터를 기록합니다.
3. `GET /api/v1/tts/jobs/{job_id}/events`가 `segment-ready` SSE 이벤트를 보냅니다.
4. 구간 URL은 작업 ID, 구간 번호, 파일명, 만료 시각을 HMAC-SHA256으로 묶습니다.
5. Web coordinator는 뒤섞여 도착한 구간을 번호순으로 준비해 같은 부분 트랙에 누적합니다.
6. 현재 구간 종료 시 다음 구간이 있으면 자동 재생하고, 없으면 `다음 구간 대기` 상태를 유지합니다.
7. 최종 병합 WAV가 준비되면 같은 트랙 ID의 음원을 최종 파일로 교체합니다.

`segment-ready` 예시:

```text
event: segment-ready
data: {"index":1,"total_segments":4,"audio_url":"/api/v1/tts/jobs/.../segments/1/audio?..."}
```

## 서명 URL 보안 경계

운영 환경에서는 다음 값을 반드시 고정합니다.

```env
SORION_SEGMENT_URL_TTL_SECONDS=900
SORION_SEGMENT_URL_SIGNING_SECRET=<32바이트 이상의 랜덤 Secret>
```

- URL은 기본 15분 후 만료되며 허용 범위는 30~3600초입니다.
- 서명은 작업 ID, 구간 번호, 실제 파일명, 만료 시각에 결합됩니다.
- 파일명은 해당 작업의 `ready_segments`에도 존재해야 합니다.
- 응답은 `Cache-Control: private, no-store`이며 공개 CDN 캐시 대상으로 두지 않습니다.
- Secret이 비어 있으면 프로세스 시작 시 임시 Secret을 만들지만, 재시작·다중 인스턴스에서는 기존 URL이 무효가 되므로 운영 준비 상태가 경고로 표시됩니다.
- 성공한 구간 파일은 일반 음원 TTL을 따르며 실패·취소 중 남은 부분 파일은 제거합니다.

## Web 재생과 지연 지표

플레이어는 하나의 값을 “첫 음성”으로 뭉치지 않고 다음을 분리합니다.

- `서버 첫 구간`: 요청 시작부터 서버가 첫 구간 파일을 준비할 때까지
- `첫 바이트`: 요청 시작부터 브라우저가 첫 오디오 데이터를 받을 때까지
- `실제 재생`: 요청 시작부터 `HTMLAudioElement.playing` 이벤트까지
- `브라우저 시작`: 요청 시작부터 Browser Speech `onstart`까지

첫 바이트와 실제 재생은 사용자가 재생을 누른 시점, 네트워크, 브라우저 버퍼링 정책의 영향을 받습니다. 따라서 서버 성능 지표와 사용자 체감 지표를 별도로 비교해야 합니다.

## 실패·복구

- SSE가 열리지 않으면 기존 작업 상태 폴링으로 전환하고 `ready_segments`를 확인합니다.
- 같은 구간 번호는 SSE와 폴링에서 중복 수신해도 한 번만 큐에 넣습니다.
- 서명 URL fetch가 403·410을 반환하면 작업 상태를 다시 조회해 같은 구간의 새 URL로 한 번 재시도합니다. 재발급에 실패하면 만료 URL을 플레이어에 넣지 않고 최종 음원을 기다립니다.
- 최종 파일 생성에 실패해도 이미 내려받아 재생 중인 브라우저 버퍼까지 강제로 회수하지는 않습니다.
- 페이지 복원 시 저장된 부분 URL을 영구 데이터로 취급하지 않습니다. 작업 ID로 다시 조회합니다.

## 현재 제한

- 준비된 후속 구간을 번호순으로 자동 재생하지만 WAV decode 경계의 틈을 실기기에서 측정하지 않았으므로 gapless를 주장하지 않습니다.
- WAV 파일 단위 전달이므로 WebSocket PCM, HLS, MPEG-DASH 같은 진짜 스트리밍은 아닙니다.
- 최종 WAV 교체 시 같은 트랙에서 현재 재생 위치와 재생 중 여부를 승계합니다. 최종 길이가 더 짧으면 끝에서 0.05초 전으로 안전하게 제한합니다.
