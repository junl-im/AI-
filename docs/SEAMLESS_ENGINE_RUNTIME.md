# Seamless Engine Runtime

Engine Heartbeat 6.8.3.3은 음성 실행 계층을 일반 사용자 화면에서 분리하고, 앱이 스스로 가장 빠른 사용 가능 경로를 찾고 유지하도록 만든 연결 안정화 패치다.

## 기술 상태 비노출

일반 작업 화면, 상단 헤더, 장문 편집기와 목소리 복제 화면에는 API 주소, Worker, GPU, 지연 시간 또는 엔진 ID를 표시하지 않는다. 사용자는 `준비됨`, `자동 준비 중`, `자동 최적화`처럼 작업에 필요한 상태만 본다. 상세 주소와 계층별 진단은 설정의 접힌 `고급 진단 및 개발자 정보` 또는 Quality 화면에서만 확인한다.

## 병렬 자동 탐색

저장 주소, 배포 runtime config, 현재 Origin과 허용된 로컬 후보를 순서대로 기다리지 않고 동시에 검사한다. 가장 먼저 정상 응답한 후보를 즉시 승격하고 나머지 요청은 취소한다. 취소된 탐색 요청은 연결 실패 이벤트로 기록하지 않는다.

## 연결 유지

- 화면이 보일 때는 20초마다 저비용 `/health` heartbeat를 수행한다.
- 백그라운드 탭은 90초 간격으로 완화해 배터리와 네트워크 사용을 줄인다.
- 120초마다 `/connectivity` 전체 상태를 갱신하고 엔진 목록 cache도 함께 준비한다.
- 온라인 복귀, 탭 복귀, 네트워크 종류 변경 시 즉시 다시 검사한다.
- 실패 시 1초부터 30초까지 단계적으로 재시도하며 브라우저 음성을 즉시 대체 경로로 유지한다.

## API와 Worker 상시 준비

API는 Worker 통신에 하나의 `httpx.AsyncClient` 연결 풀을 재사용한다. health와 readiness는 병렬로 확인하며, 15초 주기 supervisor가 Worker가 나중에 시작되거나 재시작돼도 자동으로 준비 상태를 회복한다. API 종료 시 supervisor와 연결 풀을 안전하게 닫는다. Worker의 `/ready` 호출은 모델 adapter 진단을 실행하므로 설정과 모델 무결성이 정상인 경우 시작 단계에서 메모리에 미리 준비된다.

## 첫 실행 지연 감소

- 후보 주소 순차 timeout 제거
- health와 readiness 병렬 검사
- 정상 상태에서는 통합 진단 대신 가벼운 heartbeat 사용
- 통합 진단 응답의 엔진 목록을 15초 cache로 재사용
- 브라우저 음성은 서버 연결과 무관하게 즉시 사용 가능

## 지연을 0으로 보장할 수 없는 경계

네트워크 왕복, 운영체제 음성 초기화, GPU context 생성, 모델 파일 검증과 첫 모델 적재 시간은 물리적으로 0이 될 수 없다. 이 패치는 불필요한 순차 대기와 중복 연결을 제거하고 백그라운드에서 미리 준비해 사용자가 느끼는 대기를 최소화한다. 모델이 프로세스 재시작 뒤 처음 메모리에 올라가는 cold start는 실제 장치에서 별도 측정해야 하며 임의의 성능 수치로 표현하지 않는다.

## 개인정보와 보안

자동 탐색은 저장된 허용 후보와 배포 runtime config만 사용한다. 사용자 원문, 음성 바이트, 토큰 또는 개인정보를 탐색 요청에 포함하지 않는다. Worker 인증 헤더와 기존 HTTPS·CORS·서명 경계는 그대로 유지한다.
