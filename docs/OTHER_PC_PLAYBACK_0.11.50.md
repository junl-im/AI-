# 0.11.50 다른 PC 재생 진단

GitHub Pages는 정적 Web만 제공합니다. `public/sorion-runtime-config.json`의 `apiBaseUrls`가 비어 있고 공개 HTTPS 음성 API·오디오 저장소가 배포되어 있지 않습니다. 데스크톱은 해당 PC의 `127.0.0.1:8000`을 탐색하므로 원래 PC에서 API를 실행해도 다른 PC는 그 서버와 프로젝트·음원을 자동으로 받지 않습니다. 프로젝트는 IndexedDB, 재생 대기열은 브라우저 상태와 제한된 로컬 세션에 저장됩니다.

새 PC는 첫 방문 화면에서 스튜디오 시작 전까지 Dock이 렌더링되지 않습니다. 스튜디오 진입 후에도 음원이 없는 PC에서는 빈 Dock의 배경이 투명해 재생 플레이어가 사라진 것처럼 보였습니다. 새 대사 생성은 해당 PC의 Chrome/Edge에 설치된 한국어 시스템 음성과 성우 성별 호환성에 의존합니다. 호환 음성이 없으면 트랙을 만들지 못해 Dock에도 재생 버튼이 나타나지 않았고, 작업 메시지는 구체적인 원인 대신 일반 실패만 표시했습니다. 음성 목록이 비어 있어도 생성 완료 트랙을 만들던 경우에는 실제 재생 시점에 실패할 수 있었습니다. 이번 패치는 빈 플레이어 상태, 성우 호환 진단과 사용 가능한 다른 기본 성우로 전환 버튼, 생성 실패의 실제 이유를 표시합니다. 음성 목록이 비면 완료를 가장하지 않으며, 브라우저 음성 실패를 연결 무한 재시도로 처리하지 않습니다.

다른 PC에서 **기존 음성**을 재생하려면 현재는 원래 PC에서 WAV/MP3를 다운로드해 파일로 전달해야 합니다. 사이트 안에서 자동으로 같은 프로젝트·음원을 재생하려면 별도의 공개 HTTPS API, 오디오 저장소, 접근 권한, 보존·삭제 정책이 필요합니다. 다른 PC에서 **새 음성**을 만들려면 그 PC의 한국어 시스템 음성 또는 운영 중인 음성 API가 필요합니다. 실제 다른 PC·브라우저의 음성 장치 상태는 원격으로 인증할 수 없습니다.
