# 0.11.38 · Streamed Waveform & Leaner Controls

## 완료 범위
0.11.37의 20MB/5분 Web Audio 파형 분석을 스트리밍 PCM 분석으로 교체했습니다. 사용자가 요청한 음원의 데이터를 순서대로 읽고 96개 진폭 구간만 유지하며, 전체 파일·디코딩 PCM을 보관하지 않습니다. 서버 peaks endpoint나 새 외부 라이브러리는 추가하지 않았습니다.

- 제한: 파일 총량 128MiB, 길이 60분, 앞부분 메타데이터 64KiB.
- 지원: RIFF/WAVE의 8·16·24·32비트 정수 PCM, 32비트 IEEE float, 1~8채널, 8~192kHz. 모든 채널의 peak를 반영합니다.
- 진행률, 사용자 취소, 60초 요청 제한, 재시도, 트랙 변경 시 요청 취소를 제공합니다.
- WAV byte rate·block align·data 길이를 검사하고 불완전·압축·지원 외 형식을 거부합니다. 실패해도 기존 재생·탐색은 유지합니다.
- 파형 완료 후 실제 WAV 길이로 키보드 탐색 범위를 설정합니다. 취소된 이전 분석이 재시도 결과를 덮지 않게 합니다.

메모리는 응답 chunk와 작은 잔여 프레임/헤더, 96개 peak에 비례합니다. 파일 다운로드 자체는 끝까지 필요하고 서버 peak 캐시를 제공하는 것은 아닙니다. 모바일 실기기 장시간 메모리 실측은 아직 하지 않았습니다.

## 초기 로딩
성우 선택창·음성 설정창을 열 때 해당 청크를 불러옵니다. 기존 작업공간과 세션 복구의 mount 정책은 유지합니다. 정적 테스트 계약은 지연 로딩에 맞춘 비동기 dialog 조회를 확인하도록 갱신했습니다. main JS는 519.18kB에서 510.81kB(gzip 160.54kB)로 감소했습니다. main만의 크기이며 총 전송량이나 실기기 시작 시간을 측정한 수치는 아닙니다. 500kB 경고는 남아 있습니다.

## 검증
- 웹 전체 회귀 301개와 최종 PCM 추가 회귀를 포함한 waveform 8개 검사 통과. 최종 테스트 수는 303개입니다.
- API 244 passed/1 skipped, Worker 16 passed. lint/typecheck/build·preflight·GitHub Actions를 최종 게이트로 확인합니다.
- Chrome 8개 폭에서 대본 보존·예제·가로 넘침·오류, 모바일/PC 선택창 Home/End/Escape·포커스 복귀·lazy timeline 확인.
- 모바일 폭 Chrome에서 10분 합성 WAV 파형 96개와 ArrowRight 탐색 확인. AudioContext를 사용할 수 없게 해도 통과했습니다. 이 톤은 음질 인증 증거가 아닙니다.

## 실제 음성 검증 현황
승인된 5성우 WAV·사용 권리·CosyVoice 모델 경로가 아직 제공되지 않았고 로컬 preview cache에 실제 성우 음원도 없었습니다. 따라서 계획했던 실제 Neural 생성·장문 청취·성우별 실측 조정은 보류했습니다. 음색이나 자연스러움이 청취로 검증됐다고 표시하지 않으며 0.11.37 prosody 정책은 임의로 다시 조정하지 않았습니다.

유료 API·모델 자동 다운로드·음성 자동 업로드·동시성 확대는 없습니다. 다음 버전은 실제 자산 확보 후 청취 검증과 500kB 이하 초기 청크 분할·큰 WAV 실기기 실측을 우선합니다.
