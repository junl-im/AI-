# UI GUIDE

## 모바일 기준

- 기본 검증 폭: 360px, 390px, 430px
- 터치 대상 최소 높이: 44px, 권장 52px
- 주요 행동은 한 화면에 하나만 강조
- 핵심 작업은 3번 이내 터치로 시작
- 하단 고정 내비게이션은 최대 4개 항목
- 가로 선택 목록은 스크롤 가능하되 선택 상태를 텍스트와 형태로 함께 표시

## Voice Workspace 순서

1. 읽을 문장
2. 목소리 선택
3. 말하는 느낌
4. 선택형 Advanced
5. 음성 생성
6. 재생과 다운로드

초보자는 Advanced를 열지 않아도 기본 품질로 생성할 수 있어야 합니다.

## 음성 카드

- 이름, 용도 설명, 성격 배지를 한 카드에 표시
- 선택 상태는 어두운 배경, 체크 표시, `aria-checked`로 중복 표현
- 음성 이름은 한국어로 먼저 제시
- 실제 모델이 준비되지 않은 프리셋은 사용자에게 품질 보장을 암시하지 않음

## 생성 상태

- `문장 확인 중`
- `AI 엔진 요청 중`
- `데모 WAV 준비 중`
- `음성 준비 완료`
- `생성 실패`

Mock과 브라우저 데모는 결과 카드에서 반드시 `DEMO WAV` 또는 `MOCK`으로 표시합니다.

## 결과 플레이어

- 브라우저 기본 오디오 컨트롤을 우선 사용
- 자동 재생하지 않음
- 다운로드 버튼은 출력 형식과 행동을 함께 표기: `WAV 다운로드`
- 재시도와 결과 닫기는 보조 버튼으로 배치
- 파일명은 `SoriON-YYYYMMDD-목소리-문장.wav` 규칙 사용

## 시각 언어

- Apple의 정돈된 밀도
- Notion의 단순한 정보 구조
- ChatGPT의 대화형 친근함
- 넓은 여백, 둥근 카드, 강한 제목, 절제된 애니메이션

## 애니메이션

- 일반 전환 180~300ms
- `prefers-reduced-motion` 존중
- 애니메이션이 기능 완료를 지연시키지 않음

## 한국어

- 버튼은 동사로 작성: `음성 생성 시작`
- 기술 오류를 그대로 노출하지 않음
- 존댓말을 일관되게 사용
- 줄바꿈 시 조사와 단위를 가능한 한 분리하지 않음

## 아이콘

프로젝트 원칙에 따라 SVG 파일과 SVG 아이콘 라이브러리를 사용하지 않습니다. PNG 또는 CSS·문자 기반 아이콘을 사용합니다.

## 0.3.0 엔진 상태 표현

- AI 모델 결과는 `AI AUDIO`로 표시한다.
- 운영체제 음성 결과는 `LOCAL TTS`로 표시하며 AI로 표현하지 않는다.
- 브라우저 합성 톤은 `DEMO WAV`로 표시한다.
- 엔진을 확인하는 동안 생성 버튼을 막지 않되 현재 모드를 설명한다.
- 취소 버튼은 생성 중에만 노출하고 최소 높이 40px 이상을 유지한다.

## 0.5.0 품질 연구소

- 하단 메뉴는 `만들기`, `품질`, `프로젝트`, `설정` 네 항목을 모바일 한 줄로 유지한다.
- 진단 상태는 `사용 가능`, `준비 필요`, `API 필요`를 색과 문장으로 함께 표시한다.
- A/B 비교는 최대 두 엔진으로 제한하고 선택 순서를 그대로 결과 순서로 사용한다.
- 생성 속도는 `ms/초`, 음원 크기는 `KB/MB`, 실시간 배율은 `RTF`로 표시한다.
- 지원하지 않는 감정·피치 입력은 숨기지 않고 비활성화하여 엔진 차이를 설명한다.
- 별점은 보조 평가이며 엔진 성능 점수로 자동 집계하지 않는다.

## 0.5.0 진행률 UI

- 생성 중 퍼센트는 서버 스냅샷이 있을 때만 실제 값을 사용한다.
- 장문은 `현재/전체 구간`을 함께 보여 준다.
- 진행 막대만으로 상태를 전달하지 않고 한국어 문장을 함께 표시한다.
- 취소 버튼은 생성 중 항상 한 번의 터치로 접근 가능해야 한다.

## 자동 음성 시스템 연결

API 주소 입력과 엔진 수동 선택 화면을 노출하지 않는다. 앱이 배포 설정과 안전 후보를 자동 검사하고, 상태는 compact header나 작업 화면의 비조작형 진단 문구로만 표시한다.

## 0.5.1 압축형 브랜드 배너

- 상단은 콘텐츠를 밀어내는 대형 소개 영역이 아니라 짧은 브랜드 배너로 사용한다.
- 메타 바는 `BUILD`, 모바일·PC 호환, 제작 브랜드만 한 줄에 유지한다.
- 첫 슬라이드는 `곰같은여우 SoriON AI`, 이후 슬라이드는 한 문장 메시지만 표시한다.
- 한 슬라이드에서 두 개 이상의 주장이나 버튼을 함께 노출하지 않는다.
- `AI`의 `I`와 Voice Core 마이크는 HTML·CSS로만 구성하며 SVG를 사용하지 않는다.
- PC Voice Core는 보조 장식이며 모바일 핵심 작업을 가리지 않는다.
- `prefers-reduced-motion`에서는 자동 순환을 중단하고 첫 브랜드 슬라이드를 유지한다.


## 0.6.0 목소리 복제 화면

모바일은 `녹음 → 확인·동의 → 목소리 만들기` 세 단계를 한 열로 배치한다. PC 2프레임에서도 작업 단계 카드는 주 프레임 안에서 최대 두 열만 사용한다. 품질 상태는 색상만으로 구분하지 않고 `사용 가능`, `확인 필요`, `다시 필요` 텍스트를 함께 표시한다.

Dock은 설정 메뉴를 포함하지 않는다. 메뉴는 만들기, 복제, 품질, 프로젝트 네 개이며 플레이어는 메뉴와 독립된 재생 영역이다. 대기열은 Dock 위에 열리고 모바일 화면 전체를 가리지 않는다.

## 0.6.4 생성 화면 계층

- 핵심 훅 `문장 하나면,`은 #111과 800 굵기를 사용한다.
- 보조 문장은 #7A7A7A와 600 굵기로 낮춘다.
- 생성 헤더에는 보라·파랑 radial glow를 한 개만 사용한다.
- 입력 카드는 헤더 하단과 32px 겹친다.
- 입력창, 500자 카운터, 발음 보정 토글은 첫 화면에서 숨기지 않는다.
- 목소리 프리셋은 가로 스크롤 칩으로 제공한다.
- 생성 완료 후 메인 화면은 문장별 구간 리스트를 보여주고 전체 재생은 Dock이 담당한다.

## 0.8.5 공통 작업공간 UX·IA

- 첫 랜딩과 편집 작업공간을 분리하며 Dock은 작업공간 진입 뒤에만 렌더링한다.
- 만들기 화면은 복제·품질·프로젝트·설정 이동 중 언마운트하지 않아 작성 상태를 보존한다.
- 상단 브랜드는 만들기로 복귀하고 `처음` 동작만 랜딩으로 나간다.
- 품질·프로젝트·설정은 동일한 header, eyebrow, title, description, action 구조를 사용한다.
- 하단 메뉴, 상단 현재 페이지 이름과 라우팅 순서는 하나의 내비게이션 정의를 사용한다.
- 프로젝트는 loading, error, empty, content 상태를 같은 위치에서 명확히 구분한다.
- 다크 작업공간에서 밝은 카드가 남을 경우 카드 내부 텍스트 대비를 별도로 보장한다.
- 기술 엔진 이름은 품질 진단에서만 보조 정보로 제공하고 생성 핵심 흐름은 자동으로 유지한다.

## 0.8.6 복원 UX

- 유효한 마지막 세션은 별도 선택 화면 없이 원래 작업공간과 메뉴로 복원한다.
- 복원 중인 음성 블록은 새 생성처럼 보이지 않고 “이전 작업 결과 연결 중”으로 표시한다.
- 만료된 결과는 자동 재생성하지 않고 해당 블록에 생성 버튼을 남긴다.
- 사용자가 복원 전에 입력을 시작했다면 과거 저장 내용으로 현재 입력을 덮지 않는다.
- 프로젝트의 새로 만들기는 이전 작업을 유지하는 “돌아가기”가 아니라 실제 빈 작업을 만든다.

## 0.8.6 장문 제작·브랜드·종료 UX

- 첫 제작 화면은 채팅 버블이 아니라 최대 20,000자 내용 편집기를 중심으로 구성한다.
- 내용 통계는 문자, 문단, 음성 블록, 예상 길이를 같은 행에서 제공한다.
- 일반 Enter는 줄바꿈이며 Ctrl/⌘+Enter만 제작을 시작한다.
- 생성 뒤에도 내용을 유지하고 타임라인만 새 제작본으로 교체한다.
- 공식 SoriON 아이콘을 favicon, 설치 아이콘, 첫 화면, 작업공간 상단에 통일한다.
- 상단 아이콘과 제품명은 하나의 버튼이며 모든 화면에서 첫 페이지로 이동한다.
- 첫 뒤로가기는 앱 스타일의 `alertdialog`를 표시한다.
- 확인창이 열린 상태의 두 번째 뒤로가기는 즉시 브라우저 이력을 빠져나간다.
- 공개 API 미설정은 raw URL 대신 `공개 음성 서버 배포 대기`로 표현한다.
- 첫 페이지에는 Dock을 렌더링하지 않는다.

## 0.8.7 더빙 스튜디오 UX

- 상단은 프로젝트 제목·저장 상태·엔진 상태와 주요 작업만 제공한다.
- 화자와 읽기 설정은 내용을 가리지 않는 Bottom Sheet로 연다.
- 내용 전체 제작과 문장 블록 직접 편집은 같은 프로젝트 상태를 사용한다.
- 하단 플레이어는 작업 화면에서 고정하고 첫 페이지에서는 숨긴다.
- 파괴적 초기화는 앱 내부 확인창을 거치고 공통 reset token으로 수행한다.
- 자세한 기준은 `docs/DUBBING_STUDIO_UX.md`를 따른다.


## 0.8.9 공통 제품 셸

- 만들기·복제·품질·프로젝트·설정 모두 동일한 CompactWorkspaceHeader를 사용한다.
- 왼쪽에는 공식 PNG 로고, 작은 `SoriON AI`, 제작자명과 현재 페이지명을 표시한다.
- 로고·프로그램명을 누르면 첫 페이지로 이동한다.
- 프로젝트 제목·저장 상태·프로젝트 동작은 공통 배너 아래 제작 헤더에 둔다.
- API 미연결 시 상태 칩은 `브라우저 음성`을 표시하며 AI 준비로 오인시키지 않는다.

### 공통 PageScaffold

프로젝트·품질·복제·설정은 `WorkspacePageScaffold`를 사용한다. 공통 요소는 eyebrow, 제목,
설명, 선택적 주요 액션, 상태 pill, 16px 간격의 콘텐츠 영역이다. 만들기는 장문 편집 밀도 때문에
전용 레이아웃을 유지하지만 같은 CompactWorkspaceHeader와 SoriON 홈 이동 계약을 사용한다.
